# 위험·변경 관리

> 상태: **초안** (담당은 역할 범위 기준 제안, ADR-0001)

## 위험 관리

징후가 보이면 담당이 이슈(`type:bug` 또는 `type:task`)로 올리고 완화 방법을 적용한다. 새 위험은 이 표에 행을 추가한다.

| 위험 | 영향·징후 | 담당 (제안) | 완화·대응 |
|---|---|---|---|
| 계약·문서 엔진·화면 라이브러리 결정 지연 | 통합 병목, 재작성 | R1 | 결정 기한을 이슈로 관리, 고정 응답(fixture)으로 병행 개발, 결정 전후 차이를 ADR에 기록 |
| PDF 추출 품질 부족 | 요구 누락, 잘못된 모델 | R2 | 대표 문서로 조기 실험(ADR-0004), 추출 확인 화면(HITL), 지원 범위 표시 |
| 검토 오탐·환각 | 불필요한 재작업 | R1 + 관점 담당 | 관련 문맥만 입력, 근거 필터(#18), 오탐 기준(관점 설정), 독립 결함 평가 |
| 평가 정답 누출 | 성능 과대 보고 | R3 | 개발용·평가용 세트 출처 분리, few-shot·평가 분리, 버전·해시 기록 (ADR-0014) |
| 생성 SQL 위험·잔여 객체 | 격리 DB 오염 | R4 | 허용 문장 AST 검사, 제한 계정, 트랜잭션 롤백, 잔여 객체 확인 ([11 배포](11-deployment-security.md)) |
| 공통 계약 동시 수정 | 브랜치 충돌 | R1 | `contract-change` 라벨·2인 승인, 변경 범위를 좁힌 PR, 고정 샘플 |
| 웹·PDF 출력 작업 집중 | R5 병목 | R5 | 입력·템플릿 담당 지원, API mock으로 화면 선개발 |
| 호출 비용·시간 초과 | 시연 실패 | R1 | 실행 한도·재시도 상한(ADR-0007), 호출 기록으로 단계별 비용 확인 |
| 외부 공개 자료 사용 조건 | 재배포 불가 | R2 | 출처·라이선스 기록, 원문 대량 재배포 금지, 유료 표준은 구분 원칙만 참고 |
| HWPX·HWP 추출 품질·라이선스 | 비정형 입력 지연 | R2 | 정형 입력 먼저, HWPX 조기 실험, 미지원 범위 명시 (ADR-0004, #24) |
| AWS 배포 비용·안정성 | 시연 환경 불안정 | R5 | 로컬과 같은 이미지, 예산 알림, 로컬 시연 대체 경로 (ADR-0013) |
| 확장 기능이 MVP에 섞임 | 범위 초과 | R1 | 확장은 [14 확장 기능](14-extensions.md)에 따로 두고 MVP 완료 기준에서 분리 |

## 변경 요청

승인된 요구사항·계약·평가 정답·범위를 바꿀 때는 **변경 요청 이슈**(템플릿 "Change request")로 연다. 토론·메신저의 합의도 이 이슈로 옮겨 기록한다.

| 항목 | 내용 |
|---|---|
| 변경 내용 | 변경 전 → 변경 후 |
| 근거 | 원문 요구사항·리뷰·평가 결과 등 저장소 안에서 확인 가능한 근거 |
| 영향 범위 | REQ, 에이전트, 계약(`specton/contracts/`), API, TC, 도메인 팩, 이슈 |
| 대안 | 검토한 다른 방법과 고르지 않은 이유 |
| 결정 | 승인·보류·기각, 결정자, 관련 ADR |
| 재검증 | 다시 실행할 테스트·평가와 결과 |

- 계약이 바뀌면 `contract-change` 라벨을 붙이고 2인 승인을 받는다 ([CONTRIBUTING](../CONTRIBUTING.md)).
- 설계 결정이 바뀌면 새 ADR을 쓰고 이전 ADR에 "대체됨"을 적는다 ([ADR 작성 규칙](adr/README.md)).
- 변경을 반영한 PR은 본문에 변경 요청 이슈 번호를 적고, 관련 문서(02 요구사항·12 TC 등)를 같은 PR에서 고친다.
