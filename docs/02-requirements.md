# 요구사항

> 상태: **초안** (범위는 회의 결정 전)

## 용어

| 용어 | 뜻 |
|---|---|
| 고객 | 설계할 업무의 요구사항을 작성한 사람 |
| 서비스 사용자 | 문서를 넣고 검토하는 기획자·개발자 |
| 팩 | 승인된 용어·패턴·명명 문맥. 로컬 파일 기반이며 벡터 DB를 전제하지 않는다 |
| HITL | 사용자 답변·승인을 기다리는 실행 중단/재개 지점 |
| source_ref | Excel 시트·행, PDF 페이지·블록 등 원문 위치. 내부 REQ-xx와 별도로 유지 |

ID 규칙: 이 문서의 프로젝트 요구사항은 `REQ-01`~`REQ-27`. 고객 입력을 분석해 붙이는 내부 ID도 `REQ-xx` 형식이지만 실행별로 따로 관리한다. 고객 원문 ID는 `source_id`에 그대로 보존한다. ID는 재사용하지 않는다.

## 주요 수용 기준

전체 36개 시나리오(요구사항 27 + 에이전트 9)는 [12 테스트 케이스](12-test-cases.md)에 있다. 모두 미실행이다. 구현 시 판단이 갈리기 쉬운 기준만 옮긴다.

- **조용한 누락 금지:** 오류 행·추출 실패·리뷰어 실패를 버리거나 "문제 없음"으로 바꾸지 않는다 (TC-F01·F02·F14).
- **추정으로 메우지 않기:** 우선순위 미지정 값은 근거 없이 확정하지 않는다. RTM 미연결은 LLM이 링크를 추정해 메우지 않는다 (TC-F06·F12).
- **LLM 출력 범위:** 관계 출력에 임의 FK 속성을 넣지 않는다. 존재하지 않는 기능·엔티티 참조는 거절한다 (TC-F07·F08).
- **재개·중복:** 재시작 뒤 같은 실행에서 재개하고, 오래된 revision의 답변이나 중복 resume은 409로 거절한다 (TC-F05·F19·F20).
- **라우팅:** 대상이 명확하면 A09 호출 0회. 반복·상한에서 자동 루프를 멈춘다 (TC-F16).
- **승인:** 실패 SQL이 있으면 완료 승인 대신 수정/보류만 가능하다 (TC-F17).
- **내보내기:** 최종 PDF의 한글·표·ERD가 잘리지 않고, 중간 산출물은 PDF로 만들지 않으며, 초안과 승인본을 구분한다 (TC-F18).

## 입력·출력 제약

- 비밀번호 보호·손상·추출 불가 문서는 설명과 함께 처리 실패로 표시한다.
- 스캔 PDF/OCR 지원 여부는 미정(ADR-0004). 지원하지 않으면 그 사실을 화면에 명시한다.
- 미승인 파일을 내려받으면 초안 표시를 유지한다.
- DDL 실행은 검증 DB에서만 하며 시스템 명령·확장 설치·네트워크 접근 SQL은 허용하지 않는다.

## 추적

- 요구사항 → 설계 문서 → 작업(이슈) → TC 대응은 위 요구사항 목록 표가 기준이다.
- 새 기능은 근거·영향·담당·검증 기준을 이슈로 등록한 뒤 변경한다.
