# ADR-0001: 역할 배정

- 날짜: 2026-10-25
- 상태: 승인
- 결정자: 팀 설계로 전원 (팀 회의)

## 배경

역할 5개(R1~R5)가 에이전트 9개와 주변 코드를 나눠 맡는다. 실행 제어·통합(R1)은 모든 노드를 잇는 단일 실패 지점이다. 역할표만으로는 AWS 배포와 평가 정답 제작을 맡을 사람이 드러나지 않는다.

## 결정

- 회의에서 각자 "자신 있는 것 1개 + 피하고 싶은 것 1개"를 말하고 바로 배정한다.
- R1은 LangGraph·비동기 경험이 가장 많은 사람이 맡는다.
- 역할마다 백업 1명을 둔다. R5(웹·PDF·배포 집중)의 백업은 R3을 권장한다.
- 추가 책임: AWS 배포는 R5, 평가 데이터·채점은 R2. 평가 정답 작성자는 팩 작성자와 다른 사람으로 따로 정한다 (ADR-0014).
- 첫 통합 점검 후 필요하면 재조정한다.

| 역할 | 담당 | 백업 |
|---|---|---|
| R1 실행 제어·통합 | 최태영 (@surplus96) | 미정 |
| R2 입력·분석·평가 | 김희영 (@workbaselab-ops) | 미정 |
| R3 기능·API·저장 | 박성진 (@c189021) | 미정 |
| R4 데이터 모델·검증 | 김유경 (@yugyeong-k) | 미정 |
| R5 관계·시각화·웹 | 김순재 (@kisoja24782-ux) | 미정 |

백업 담당은 첫 통합 점검 때 정한다.

## 검토한 대안

| 대안 | 장점 | 단점 | 기각 이유 |
|---|---|---|---|
| 첫날 반나절 시험 구현 후 배정 | 적성 확인 가능 | 10일 중 반나절 소모 | 기간이 짧아 바로 착수가 우선 |

## 결과

- 좋아지는 점: 바로 착수할 수 있다.
- 감수할 점: 적성이 맞지 않으면 재조정 비용이 든다.
