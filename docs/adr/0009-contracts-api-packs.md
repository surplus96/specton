# ADR-0009: 데이터 계약·API·도메인 팩 형식

- 날짜: 2026-10-23 (계약 승인 2026-10-26)
- 상태: 계약 승인, 도메인 팩 제안
- 결정자: 팀 설계로 (계약은 PR #48 리뷰에서 R1 승인, 팩은 #11에서 결정)

## 배경

에이전트 담당 5명이 같은 계약을 쓰므로 먼저 동결해야 병렬 구현이 가능하다. 도메인 팩은 공공데이터 공통표준 8차(2025-11)로 초안을 만들었고 형식 결정이 남아 있다.

## 결정

### 계약 (승인)

- [05 데이터 계약](../05-data-contracts.md), [06 API](../06-api.md), [api/openapi.json](../api/openapi.json)을 기준으로 계약을 동결한다. ADR-0006을 반영한다. PR #48 병합 시점이 동결 시점이다.
- `source_ref`는 **구조체**(`kind`별 `sheet`/`row`/`page`/`block`/`section`/`paragraph`/`table`/`cell`)다. 행·쪽은 1부터, 블록·구역·문단·표는 0부터 센다. 화면 표기는 코드가 만든다.
- 계약 구현은 `specton/contracts/`의 Pydantic 모델이며 LLM 출력(`*Draft`)과 저장 모델을 나눈다. 모든 계약 모델은 불변(`frozen`)이고 목록 필드는 튜플이다. 값을 바꿀 때는 검증을 다시 거치는 `evolve`를 쓴다.
- 속성 제약 표현(`check`)은 계약에 두지 않는다. 중복 금지만 `is_unique`로 두고, 값 범위 등 허용 범위는 규칙 검사(#15)에서 정한 뒤 추가한다.
- 오류 코드는 06 문서의 16개다. 실행 실패 원인(`LLM_REFUSED`·`LLM_OUTPUT_INVALID`·`LLM_UNAVAILABLE`·`BUDGET_EXCEEDED`·`EXTRACTION_FAILED`)을 `INTERNAL`과 구분한다.
- 동결 후 계약 변경은 `contract-change` 라벨과 2인 승인을 거친다.

### 도메인 팩 (제안, #11)

| 항목 | 제안 |
|---|---|
| 타입 프로필 | `strict` (일자 char(8), 여부 char(1) Y/N). 대안 `pg_native` |
| 조합 코드 길이 | 업무 코드 `코드C10`, 유형·상태 코드 `코드C2` (실제 코드 체계로 확정) |
| 공유 용어 | 사용여부·변경일시·변경사유를 `common/terms.yaml`로 이동 |
| 공유 패턴 | 사용 중지 패턴을 `common/patterns.yaml`로 이동 |
| 명명 규칙 빈칸 | 테이블 접두어(TB_ 등), PK·FK 명명, 용어당 최대 단어 수 |
| 공통표준 판 | 8차 CSV 사본 고정. 9차(2026-11 예정) 반영 여부 결정 |
| 평가 자료 | 팩 밖에 두고 공개 저장소에 올리지 않음 |
| 팩 파일 형식 | Pydantic 모델로 고정, 로더·검증 테스트 |

## 검토한 대안

| 대안 | 장점 | 단점 | 기각 이유 |
|---|---|---|---|
| 계약 없이 각자 구현 후 통합 | 초기 속도 | 통합 시 대규모 수정 | 병렬 개발 불가 |

## 결과

- 좋아지는 점: 모든 에이전트를 고정 응답으로 동시에 개발할 수 있다.
- 감수할 점: 동결 후 계약 변경은 `contract-change` 라벨과 2인 승인이 필요하다.
