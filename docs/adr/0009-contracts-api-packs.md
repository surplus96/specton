# ADR-0009: 데이터 계약·API·도메인 팩 형식

- 날짜: 2026-10-23
- 상태: 제안
- 결정자: 팀 설계로 (회의에서 승인·수정·보류)

## 배경

에이전트 담당 5명이 같은 계약을 쓰므로 먼저 동결해야 병렬 구현이 가능하다. 도메인 팩은 공공데이터 공통표준 8차(2025-11)로 초안을 만들었고 형식 결정이 남아 있다.

## 결정

- [05 데이터 계약](../05-data-contracts.md), [06 API](../06-api.md), [api/openapi.json](../api/openapi.json)을 기준으로 계약을 동결한다. ADR-0006을 반영한다.
- `source_ref` 표현은 **구조체**(`kind`별 `sheet`/`row`/`page`/`block`/`section`/`paragraph`/`table`/`cell`)로 제안한다. 화면 표기는 코드가 만든다. 동결 때 확정한다.
- 계약 구현은 `specton/contracts/`의 Pydantic 모델이며 LLM 출력(`*Draft`)과 저장 모델을 나눈다 ([05](../05-data-contracts.md)).
- 도메인 팩:

| 항목 | 제안 |
|---|---|
| 타입 프로필 | `strict` (일자 char(8), 여부 char(1) Y/N). 대안 `pg_native` |
| 조합 코드 길이 | 업무 코드 `코드C10`, 유형·상태 코드 `코드C2` (실제 코드 체계로 확정) |
| 공유 용어 | 사용여부·변경일시·변경사유를 `common/terms.yaml`로 이동 |
| 공유 패턴 | 사용 중지 패턴을 `common/patterns.yaml`로 이동 |
| 명명 규칙 빈칸 | 테이블 접두어(TB_ 등), PK·FK 명명, 용어당 최대 단어 수 |
| 공통표준 판 | 8차 CSV 사본 고정. 9차(2026-11 예정) 반영 여부 결정 |
| 평가 자료 | 팩 밖에 두고 공개 저장소에 올리지 않음 |
| 팩 파일 형식 | Pydantic 모델로 고정, 로더·검증 테스트 |

## 검토한 대안

| 대안 | 장점 | 단점 | 기각 이유 |
|---|---|---|---|
| 계약 없이 각자 구현 후 통합 | 초기 속도 | 통합 시 대규모 수정 | 병렬 개발 불가 |

## 결과

- 좋아지는 점: 모든 에이전트를 고정 응답으로 동시에 개발할 수 있다.
- 감수할 점: 동결 후 계약 변경은 `contract-change` 라벨과 2인 승인이 필요하다.
