# ADR-0003: 입력 양식

- 날짜: 2026-10-23
- 상태: 제안
- 결정자: 팀 설계로 (회의에서 승인·수정·보류)

## 배경

고객 요구사항 정의서 양식은 공공 7칸(ID·명칭·상세·분류·산출정보·관련 요구사항·출처), 스마트공장 11칸, 민간 자체 양식 등으로 다양하다.

## 결정

- 기준 열: 요구사항 ID · 구분 · 요구사항명 · 상세 내용 · 출처, 선택 열: 관련 요구사항.
- 다른 양식은 열 매핑 YAML로 기준 열에 맞춘다. 매핑 키는 영문(`source_id`, `category`, `name`, `description`, `source`, `related_ids`)으로 쓴다.
- 병합 셀·다중 시트·헤더 위치 차이 중 지원하지 않는 것은 오류로 안내한다.

## 검토한 대안

| 대안 | 장점 | 단점 | 기각 이유 |
|---|---|---|---|
| 공공 7칸을 기준으로 | 공공 사업 양식과 일치 | 합성 데이터 제작 비용 증가 | 민간 양식 흡수가 어려움 |

## 결과

- 좋아지는 점: 양식이 달라도 매핑만 추가하면 된다.
- 감수할 점: 실제 엑셀의 불규칙한 구조는 파서가 견뎌야 하는 문제로 남는다.
