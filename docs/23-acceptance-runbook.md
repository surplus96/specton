# 재고 팩 최종 시연·인수 실행 안내 (#23)

## 로컬 브라우저 인수 결과 (2026-11-11)

R1 지시에 따라 Codex가 실제 Chromium UI를 자동 조작했다. main `36aed86`, 운영 팩
common 0.1.7·inventory 0.1.23과 실제 LLM을 사용했으며 탐색 사전이나 평가 원문을 넣지 않았다.
README와 같은 공개 합성 CSV에 재고 부족 알림 문장을 추가해 분석 확인을 시연했다.

- 잘못된 CSV 업로드의 파싱 실패와 오류 보존, 새 문서 업로드로 재시작 확인.
- 분석 확인 중 새로고침·오프라인/재연결 후 같은 interrupt 복구 확인.
- UI에서 알림 기준을 10개 미만으로 수정하고 실제 설계·검토·UI 승인 후 revision 1 완료.
- UI에서 실제 저장한 7개 형식의 파일과 API 승인 목록 해시 일치, 승인 manifest 별도 검증.
- 완료 화면 새로고침 후 상태·revision 유지, 페이지 오류 0건.
- 기능 명세 PDF 2쪽·ERD PDF 5쪽 모두 렌더링해 한글·표·CRUD·도면 잘림 없음과 승인 표식 확인.

다운로드 계측 도구의 응답 버퍼가 빈 값으로 나와, 같은 실행에서 브라우저가 디스크에 저장한
실제 파일 바이트로 재검증했다. 추가 LLM 실행으로 결과를 교체하지 않았다. 호출 8회,
추정 USD 0.092588665이며 청구서 금액이 아니다. 소규모 합성 입력·로컬 macOS/Chrome 범위다.
[비식별 인수 집계](evidence/23-local-browser-acceptance-20261111.json)를 따른다.

최신 main의 #324는 평가 전용 통제 조건만 보완했고 이번 생산 API·UI 경로는 바꾸지 않았다.
AWS 최신 서버 재배포·서버 TC-F19, 릴리스 태그·최종 인수는 아직 완료하지 않았다.
사용자가 서버 접속 정보를 이후 전달하기로 해 배포는 대기한다. #22의 잔여 판정도 유지한다.
비공개 상세 증거 보존일은 2026-12-11로 기록했으며 자동 삭제는 수행하지 않는다.

R1이 릴리스 후보를 확인한 뒤 브라우저에서 직접 실행할 절차다. 이 문서 작성은 실제 시연·승인·태그 생성의 완료 기록이 아니다. 필수 범위는 재고 팩이며 설비 팩은 선택 후속이다. #22의 후보 결함·실제 평가 결과와 #25 담당자의 AWS 인계를 먼저 확인한다.

## 시작 기준과 기록

README의 [설치·첫 실행](../README.md#첫-실행)에서 만든 합성 CSV를 사용한다. 승인된 비공개 평가셋이나 고객 원문을 시연 입력으로 바꾸지 않는다. 화면·영상·오류 캡처에도 키와 비공개 문서가 들어가지 않게 한다.

후보 checkout에서 아래 읽기 전용 검사를 실행하고 결과를 인수 기록에 붙인다.

```bash
git rev-parse HEAD
git status --short
uv run python -m specton.packs.build --check
curl --fail http://localhost:8000/health
```

| 기록 항목 | 적을 값 |
|---|---|
| 대상 | 후보 PR·병합 커밋·시연 날짜·담당자 |
| 환경 | 로컬 새 환경 또는 AWS 주소·OS·브라우저·실행 이미지 ID |
| 고정 값 | uv.lock 해시·팩 버전·policy_digest·계약/프롬프트·설계/검토 모델·검토 방식 |
| 입력 | 합성 CSV 해시·업로드 run_id·수정 전후 revision |
| 제한 | 실제 평가의 완료/미완료/미실행 지표·알려진 미지원·열린 결함 |
| 결과 | 시나리오별 통과/실패/미실행·캡처 위치·후속 이슈 |

태그는 위 후보와 일치하는 병합 커밋에 R1이 최종 인수 후 생성한다. 미병합 PR의 측정 결과를 릴리스 버전의 검증 결과로 기록하지 않는다.

## 브라우저 시나리오

| 순서 | R1의 조작 | 확인할 결과·증거 |
|---|---|---|
| 1 | 웹에서 합성 CSV 업로드, inventory 선택 | 실행 식별자와 원문 위치가 보이고, 추출 확인이 필요하면 확인 화면으로 이동 |
| 2 | 분석 확인에서 근거 있는 한 문장 수정·확정 | 원문과 확정 요구사항을 함께 확인. 확인 항목이 없어 화면을 건너뛴 실행은 별도로 기록하고 수정 시연을 통과로 세지 않음 |
| 3 | 설계·검토 작업공간에서 원문→요구사항→기능·모델→지적을 탐색 | 같은 revision의 연결을 유지. critical·사람 조치가 있으면 승인 차단을 확인하고 원인을 남김 |
| 4 | 진행 중/사람 확인 중 새로고침, 잠시 네트워크를 끊고 복구 | 현재 상태와 질문 복원, 이벤트·지적 중복 없음, 답을 중복 제출하면 한 번만 적용 |
| 5 | 최종 검토에서 근거를 확인한 뒤 승인 | 승인 revision과 생성 모델 일치. 승인 전 초안의 공개 다운로드를 허용하지 않음 |
| 6 | 산출물 목록에서 기능 명세·ERD·DDL·RTM·manifest 다운로드 | 목록에 실제 생성된 형식만 대상. 파일 해시와 manifest·목록의 해시 일치, PDF 한글/표/ERD 잘림과 승인 표식 육안 확인 |
| 7 | 이력 화면에서 같은 실행 다시 열기 | 승인 상태와 내려받은 바이트·revision 유지 |

모델이 같은 입력에서 다른 지적·재작업 횟수를 낼 수 있으므로 고정 지적 건수나 완료 시간을 합격 조건으로 쓰지 않는다. 최종 검토까지 가지 못하면 실패·미완료로 기록하고, 화면 확인에 성공했다는 이유로 전체 실행을 통과로 바꾸지 않는다.

## 실패·재개와 환경 인계

사람 확인에서의 재개와 실패 종료 뒤 재시작을 구분한다. 동일 run에서 복구가 지원되는 상태인지 화면과 API 안내를 먼저 확인한다. 이미 `failed`로 끝난 run을 무조건 이어 실행할 수 있다고 약속하지 않는다.

| 시나리오 | 확인·기록 |
|---|---|
| 사람 확인 재개 | 현재 interrupt에 답한 뒤 다음 단계 진행, 오래된 interrupt/revision의 중복 답은 거절 |
| 차단·실패 | 원인·조치 안내와 현재까지의 결과 보존. 미지원 이름은 RULE-05·critical·사람 조치를 유지하며 승인 우회 금지 |
| 재시작 | 복구 가능한 설정/입력을 조치한 뒤 UI가 제공하는 재실행 또는 새 업로드로 진행하고 이전 run과 연결해 기록 |
| AWS·재배포 | #25 담당자가 배포 커밋/이미지·컨테이너 교체·백업 복구 증거를 인계. R1은 같은 재고 시나리오를 AWS 브라우저에서 확인 |

검증 도중 장애를 만들기 위해 팀원의 배포 환경이나 공용 키를 변경하지 않는다. 필요한 실패 주입은 격리 환경을 사용하고, 자동 stub·HTTP 시험과 실제 브라우저 확인 범위를 구분한다.

## 인수 완료 기록 양식

아래 항목은 실행 뒤 R1이 실제 결과로 작성한다. 미실행은 그대로 남긴다.

```text
후보/병합 커밋:
환경/브라우저/날짜:
입력 해시/run_id/revision:
로컬 시나리오 결과와 캡처:
AWS 시나리오 결과와 #25 인계 근거:
실패·재개/새로고침·재연결 결과:
다운로드·해시·PDF 육안 확인:
실제 평가/미지원/남은 결함 인수 여부:
비밀값·개인 원문·임시 파일 제외 확인:
R1 최종 판단/릴리스 태그:
```

실제 실행·다운로드 해시·평가 자료는 팀 비공개 위치에 보관한다. 공개 이슈에는 집계·판정·비식별 캡처만 남긴다. 시연 업로드와 인수 증거의 보존 기간·보존 사유·삭제 예정일은 시연 전에 R1이 인수 기록에 정한다. 삭제할 때 원문·산출물·상태·체크포인트·백업 사본을 함께 처리하는 [자료 수명주기](11-deployment-security.md#자료-수명주기)를 따른다.
