# 확장 기능

> 상태: **초안** (MVP 범위 밖. 착수 시 별도 이슈·ADR로 범위를 정한다)

MVP 완료 기준([01 개요](01-overview.md#완료-기준))에 넣지 않는다. 확장에 필요한 에이전트 수·도구는 기본 9개(A01~A09)에 포함하지 않으며 착수할 때 정한다.

| 확장 | 목표 | MVP와의 연결 |
|---|---|---|
| EXT-01 외부 리서치 기반 도메인 설계 | 팩에 없는 도메인의 요구를 분석하고 외부 자료를 모아 설계 문맥과 기획 초안을 만든다 | 미지원 팩 안내 후 별도 조사 실행·사용자 승인으로 진입 |
| EXT-02 업무 구현·오픈소스 연동 | 승인된 네 산출물로 업무 API·서비스·DB를 구현하고 오픈소스 재고·설비 시스템에 연동해 동작을 검증한다 | 승인된 기능 명세·ERD·DDL·RTM을 입력으로 쓴다 |
| EXT-03 요구사항 변경 대응 | 승인 이후 요구사항이 바뀌면 이전 버전과 비교해 영향받는 기능·엔티티·테이블을 찾고 산출물과 RTM을 새 버전으로 만든다 | MVP의 revision·model_snapshot·RTM 추적을 재사용 |

- EXT-01의 지식 기반은 지금의 로컬 도메인 팩에서 출발한다. 벡터 DB·RAG는 구현되어 있지 않다.
- 기존 quality 팩은 도메인 확장 후보로 남긴다.

## EXT-01 외부 리서치 기반 도메인 설계

```text
미지원 도메인 요구 분석 → 부족한 지식·질문 목록 → 공식 자료 우선 검색
  → 출처·확인일·라이선스·인용 위치 기록 → 충돌·가정 정리 → 팩·기획 후보 생성
  → 사용자 확인 → 팩 버전 고정 → 기존 설계 흐름 실행
```

- 외부 원문은 신뢰하지 않는 입력이다. 그 안의 지시를 프롬프트 명령으로 따르지 않는다.
- 정할 것: 검색 권한·대상, 시간·비용 한도, 외부 전송 정책.
- 자료가 부족하면 "미검증"으로 남기고 업무 정책을 사실처럼 채우지 않는다.
- 결과물: 출처 목록, 근거-요구 대응표, 용어·패턴 후보, 남은 질문, 팩 manifest.
- 자동 검색 결과를 평가 정답으로 바로 쓰지 않는다.
- 검증: 출처 실재, 인용 일치, 도메인 적합성, 상충 정보, 중복 제거, 승인 전 팩 적용 차단.

## EXT-02 업무 구현·오픈소스 연동

1. 승인된 모델·기능·RTM과 업무 수용 기준을 고정한다.
2. 선택한 업무 흐름의 DB·API·서비스 코드를 생성하고 구조·동작을 검증한다.
3. 대상 오픈소스 제품의 버전, 무료 배포 범위, 라이선스, 공식 API, 인증 방법을 실증한다.
4. 엔티티·업무 코드·단위·상태·외부 ID 매핑과 데이터 소유권을 정한다.
5. 공식 API를 쓰는 어댑터를 만들고 정상·실패·중복·재시도·취소를 검증한다.
6. 개발 환경의 결과와 코드·DB·TC·배포·외부 호출 추적을 RTM에 연결한다.

- 생성 DDL을 오픈소스 제품의 내부 DB에 직접 적용하지 않는다. 제품 내부 스키마와 새 설계는 다를 수 있으므로 연동은 공식 인터페이스와 매핑으로 한다.
- openMAINT 등의 예시는 연동 대상 확정이나 API 사용 가능성의 증거가 아니다. 대상 제품은 착수 시 ADR로 정한다.
- 기능 명세서만으로 부족한 처리 순서·권한·상태·원자성은 실행 명세로 보완한다.

## EXT-03 요구사항 변경 대응

```text
변경 요청 → 새 요구사항 revision → 이전 승인 버전과 요구사항 비교
  → req_ids 역추적으로 영향받는 기능·엔티티·관계·테이블 식별
  → 영향 범위만 재설계(가능하면 해당 target_stage부터) → 산출물·RTM 새 버전 → 변경 이력·재승인
```

- 검증: 바뀌지 않은 요소의 ID 유지, 삭제된 요구에 연결된 요소의 보류 표시, 영향 누락 탐지.
- 변경 요청은 [13 위험·변경 관리](13-risks-changes.md#변경-요청)의 양식을 쓴다.
- 수정 순서·이력 관리 방식은 현업 의견을 받아 착수 시 상세화한다.

## 구현 후보와 열린 질문

- 첫 수직 흐름 후보는 재고 수불 확정·취소, 그다음 예방 작업 생성·수행·승인이다.
- 범용 CRUD만으로 원장 불변성·음수 재고 금지·권한·상태 전이가 완성되지 않는다.
- 기존 데이터 마이그레이션, 운영 배포, 전체 업무 UI는 별도 범위다.

착수 시 정할 확장 결정표:

| 항목 | 정할 내용 |
|---|---|
| 지원 업무 | 대상 REQ와 업무 흐름 |
| 실행 계약 | 생성 방식, 지원 밖 요청 처리 |
| 대상 제품 | 제품·버전·API·권한 |
| 데이터 | 소유권, 중복 키, 동기화 상태 |
| 장애 | 재처리·보상 정책 (전체 원자성이 불가능한 연동은 요구사항으로 명시) |
| 검증 | 픽스처, 비용·실행 환경 |
| 담당 | 추가 에이전트와 담당자 |
