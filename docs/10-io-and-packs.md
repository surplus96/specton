# 문서 입출력·도메인 팩

> 상태: **초안** (엔진·양식은 회의 결정 전)

## 입력 처리 원칙

- 정형(Excel·CSV)을 먼저 구현하고 비정형(PDF → HWPX·HWP)을 연결한다.
- 모든 형식이 같은 단계를 거친다: **추출 → 스키마 구조화(원문 기호 보존) → 원문 대조 검증 → 사용자 확인**.
- ①·•·가. 같은 원문 기호와 번호는 정규화하면서 지우지 않는다.
- 원문 `source_ref`와 추출본을 보존하고, 추출본은 사용자가 고치지 않는다. 추출 확인 결정(확인·제외)과 사유는 원문 블록에 따로 남긴다 (ADR-0015). 추출 오류가 분석 품질 오류와 섞이지 않게 평가한다.
- 업로드 파일명을 저장 경로로 쓰지 않는다. 입력은 비신뢰 데이터다.

## Excel·CSV

| 항목 | 기준 |
|---|---|
| 기준 열 (제안, ADR-0003) | 요구사항 ID · 구분 · 요구사항명 · 상세 내용 · 출처 + 선택 "관련 요구사항" |
| 다른 양식 | 공공 7칸(ID·명칭·상세·분류·산출정보·관련 요구사항·출처), 스마트공장 11칸 등은 열 매핑 YAML로 기준 열에 맞춤 |
| 구분 열 | 원문값으로 보존. FR/NFR 정답으로 강제 해석하지 않음 |
| Excel | openpyxl로 값·시트/행 위치 보존. 수식은 실행하지 않음. 캐시값이 없거나 의미가 불명확하면 사용자 확인. 매크로 파일 불허. 병합 칸은 왼쪽 위 값으로 채우고, 요구사항 ID 칸이 세로 병합된 행들은 1건으로 묶는다 |
| CSV | Excel과 같은 열 매핑. 인코딩(UTF-8·CP949, BOM 있는 UTF-16)·구분자 확인, 행 번호를 `source_ref`로 |
| 지원 밖 | 병합 셀·다중 시트·헤더 위치 차이 중 지원하지 않는 것은 오류/확인 대상으로 안내 |

## PDF

| 유형 | 처리 |
|---|---|
| 텍스트형 | 페이지·블록·읽기 순서 보존, 원문 대조 |
| 표형 | 셀/행 연결과 페이지 경계 확인 후 요구사항 블록으로 정규화 |
| 스캔 | OCR 포함 여부 미정 (ADR-0004). 미지원이면 명시 |
| 암호화·손상 | 오류와 지원 경계 안내, 추출 성공으로 처리하지 않음 |
| 도면 중심 | 도면에서 요구사항을 추론하는 기능은 범위 밖 |

- 엔진 제안: Docling(표 구조·OCR), 텍스트형이 느리면 pdfplumber 보조 (ADR-0004). 대표 PDF 2~3건으로 실측 후 확정.
- 추출 confidence를 항상 얻을 수 있다고 가정하지 않는다. 빈 블록·문자 깨짐·분리된 행으로 검토 플래그를 만든다.

## HWPX·HWP

| 유형 | 처리 |
|---|---|
| HWPX | 요구사항 상세표를 읽어 구역·문단·표·셀 위치를 `source_ref`로 (`specton/ingest/hangul.py`) |
| HWP 5.0 | 엔진은 바로 읽을 수 있지만 업로드는 아직 받지 않는다(`.hwp`는 415와 HWPX 변환 안내, `specton/api/uploads.py`) |
| 배포용·암호화·손상 | 오류와 지원 경계 안내 |

- 엔진: HWP 5.0·HWPX 모두 `rhwp-python==0.8.1`(MIT)로 읽는다(2026-11-08 채택, ADR-0004). 엔진 호출은 `specton/ingest/hangul_engine.py` 한 곳이다.
- 원문 위치는 구역·문단·표·셀로 적고, 렌더링 쪽 번호를 원문 쪽 번호로 쓰지 않는다.
- 지원 여부를 화면에 명시한다.

## 도메인 팩

구조와 작업 방법은 [domain_packs/README](../domain_packs/README.md).

- `common`: 명명·타입·공통 규칙 (공공데이터 공통표준 8차, 2025-11 기준)
- `inventory`(재고·자재) 먼저, `maintenance`(설비) 이어서. 공통 코드는 그대로 두고 팩만 바꾼다.
- manifest에 이름·버전·출처·origin·승인 상태를 기록한다.
- 팩 값의 근거와 출처는 [common 근거](../domain_packs/common/RATIONALE.md), [maintenance 근거](../domain_packs/maintenance/RATIONALE.md)에 둔다.
- 미지원 도메인의 자동 외부 검색은 후속 확장(EXT-01)이다.
- 개발용 합성 요구사항(재고 INV-xxx, 설비 MNT-xxx)은 팩 보완·few-shot에만 쓴다. 세트 전체는 공개 저장소에 올리지 않고, few-shot에 넣는 범위는 [07 테스트·평가](07-testing-eval.md#평가-데이터)를 따른다. 정답 ERD·DDL을 평가 입력에 함께 넣지 않는다.
- 팩의 `patterns.yaml`에 있는 `development set assumption Axx`는 개발용 세트 문서의 가정 번호다. 에이전트 ID(A01~A09)와 다르다.

### 팩 형식 결정 사항 (ADR-0009)

| 항목 | 현재 초안 |
|---|---|
| 타입 프로필 | `strict` (일자 char(8), 여부 char(1) Y/N) / 대안 `pg_native` |
| 조합 코드 길이 | 업무 코드 `코드C10`, 유형·상태 코드 `코드C2` (임시) |
| 공유 용어·패턴 | 두 팩에 중복. `common/terms.yaml`·`common/patterns.yaml` 신설 여부 |
| 명명 규칙 빈칸 | 테이블 접두어, PK·FK 명명, 용어당 최대 단어 수 |
| 공통표준 판 | 8차 CSV 사본 고정. 9차(2026-11 예정) 반영 여부 |
| 팩 파일 형식 | Pydantic 모델로 고정 (로더·검증 테스트) |

## 출력 규격

| 산출물 | 형식 | 필수 내용 |
|---|---|---|
| 요구사항 분석 | Markdown (중간) | source_id·REQ-xx·원문 위치·분류·질문 |
| 기능 명세서 | Markdown + 최종 PDF | 기능 ID·설명·우선순위/근거·req_ids·CRUD |
| ERD | Mermaid + 최종 PDF | 엔티티·속성·키·관계·선택 여부, 모델 버전 |
| DDL | SQL | PostgreSQL 대상·모델 버전·검증 상태 |
| RTM | Excel·CSV | 원문 요구 → 기능 → 엔티티/관계, 미연결·보류 표시. 추출 확인에서 뺀 원문은 「제외」 행과 사유(없으면 판정 이유), 원문 문장 없이 확인한 행은 「확인(원문 없음)」 행과 판정 이유로 남기며 둘 다 미연결로 세지 않는다 (ADR-0015) |
| 검토 보고서 | Markdown (중간) | source별 지적·근거·수정 이력·검증/승인 상태 |

- PDF는 승인 시점에 최종 Markdown·Mermaid를 변환해 1회 만든다 (확정).
- 기능 명세서 Markdown(`specton/codegen/function_spec.py`, #14)은 문서 정보(`run_id`·`revision`·`model_hash`·`pack`·`pack_version`, ERD PDF 표지와 같은 이름) → 기능 목록 → 기능 상세 → CRUD 매트릭스(면제 근거 포함) 순서다. 제목·문단·글머리표·굵게·인라인 코드·파이프 표만 쓰고(글 안의 `\`·`*`·`` ` ``는 역슬래시로, 표 칸의 `|`는 그 뒤에 이스케이프), 초안 표시는 넣지 않는다(승인본이 같은 바이트라 초안 구분은 파일 이름·PDF가 한다).
- PDF 엔진: WeasyPrint(HTML/CSS → PDF) + `mermaid-cli`(SVG), Mermaid 11.15.0. 기능 명세서와 ERD가 같은 엔진을 쓴다. ERD가 깨지면 Playwright 인쇄로 전환 (ADR-0004 승인).
- 한글 폰트(Noto Sans CJK KR)·긴 표 페이지 분할·머리글 반복·ERD 배율은 실측으로 확인했다. ERD는 개요 + 영역별 상세도(키 속성만) + 테이블 정의서로 나누고, 넓은 표는 가로 쪽에 두되 넘치면 열을 나눈다 (ADR-0004 「PDF 출력 실측」).
- 렌더러가 외부 경로·URL 리소스를 가져오지 못하게 제한한다.

### 출력 manifest

`run_id`, `revision`, `model_hash`, `source_hash`, 팩·프롬프트·생성기 버전, 승인 상태, 파일별 해시. 초안과 승인본의 내용 버전을 섞지 않는다.

- 구현: `specton/codegen/manifest.py` `build_manifest`·`render_manifest`(키 순서를 고정한 JSON, #14). 한 manifest에는 현재 revision·현재 모델·같은 승인 상태의 파일만 넣고, 섞이면 만들지 않는다. 생성기 버전은 모델 정리 규칙 버전·이름 규칙 해시다. 내려받기·승인본 게시에 붙이는 연결은 #17·#13에서 한다.
- RTM(`specton/codegen/rtm.py`, #14): 시트 「RTM」(원문 ID·원문 위치·요구사항 ID·상위 요구사항·요구사항·유형·기능·엔티티·관계·상태·비고)과 「문서 정보」(기능 명세서와 같은 문서 정보 + 상태별 건수). CSV는 같은 행을 UTF-8(BOM)·CRLF로 쓴다. 상태는 `연결`(기능에 하나라도 연결)·`미연결`·`제외`·`확인(원문 없음)`이고, 연결은 `req_ids` ID 조인만 쓴다. 같은 입력이면 같은 바이트다(xlsx 작성 시각 고정). 글 칸은 수식이 아닌 문자열로 쓰고(CSV는 `=`·`+`·`-`·`@`·탭·CR로 시작하면 앞에 `'`), 엑셀 한 칸 한도(32,767자)를 넘는 글은 「긴 글」 시트에 조각으로 모두 남긴다.
- **잔여 — 「보류」 표시:** 위 출력 규격 표의 「보류」는 계약에 명시적 보류 판정·사유가 없어 아직 만들지 않는다. 비기능이라는 이유만으로 보류를 자동 생성하지 않고, 기능 연결이 없으면 `미연결`로 둔다. 보류 기준·기록 방식이 정해지면 후속으로 더한다 (#215 R1 기준).
