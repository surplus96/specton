# common 팩 근거

> 상태: **초안** (조사일 2026-10-23, 공공데이터 공통표준 8차 기준. 타입 프로필은 ADR-0009 도메인 팩 항목에서 결정)

`naming.yaml`·`rules.yaml`·`words.yaml`·`domains.yaml` 값의 출처와 판단 근거다. 값마다 근거 등급을 단다.

| 등급 | 뜻 | 예 |
|---|---|---|
| `official` | 고시·공식 CSV 원문 | 단어 약어, 도메인 타입·길이, 공식 용어 변경 금지 |
| `observed` | 공식 데이터를 전수 관찰한 사실 (명문 규칙 아님) | 대문자 약어, `_` 연결, 약어 2~6자, 분류어가 마지막 |
| `project` | 국가 규칙이 없어 팀이 정함 | 테이블 접두어, PK·FK 명명, 준수율 산식, PostgreSQL 타입 프로필 |

## 1차 출처

- 공공데이터 공통표준 8차 제·개정(2025-11) CSV 3종: [단어](https://www.data.go.kr/data/15156439/fileData.do) 3,284행, [용어](https://www.data.go.kr/data/15156379/fileData.do) 13,176행, [도메인](https://www.data.go.kr/data/15156442/fileData.do) 129행. 사본은 `domain_packs/sources/`에 고정한다.
- 법적 근거: 「공공기관의 데이터베이스 표준화 지침」 행정안전부고시 제2025-19호 ([국가법령정보센터](https://www.law.go.kr/LSW/admRulLsInfoP.do?admRulSeq=2100000255382)).
- 도메인 데이터셋의 다음 등록 예정일은 2026-11-01이다. **9차판이 나오면 팩 동결 전에 반영 여부를 정한다** (ADR-0009).
- CSV는 BOM이 붙은 UTF-8이고 `"금액N22,2"`처럼 쉼표가 든 도메인명은 따옴표로 감싸져 있다. 생성기(`specton/packs/build.py`)가 이를 처리한다.

## 분류어와 일반단어

공식 단어 CSV의 형식단어여부(Y)가 분류어다. 팀이 처음 잡은 "분류어 14개" 중 공식 분류어는 **11개**다.

| 단어 | 약어 | 형식단어 | 도메인 분류 | 비고 |
|---|---|---|---|---|
| 코드 | CD | Y | 코드 | |
| 명 | NM | Y | 명 | 이음동의어: 이름, 명칭 |
| 번호 | NO | Y | 번호 | |
| 일자 | **YMD** | Y | 연월일 | DT가 아님 |
| 일시 | **DT** | Y | 연월일시분초 | |
| 내용 | CN | Y | 내용 | |
| 여부 | YN | Y | 여부 | |
| 순서 | SEQ | Y | 순서 | |
| 수량 | QTY | Y | 수 | |
| 단가 | UNTPRC | Y | 금액 | |
| 금액 | AMT | Y | 금액 | |
| 상태 | STTS | **N** | – | 수식어. `*_STTS_CD`처럼 코드·명 앞에 붙는다 |
| 구분 | SE | **N** | – | 수식어. `*_SE_CD` |
| 일수 | 미등록 | – | – | 일(DAY) + 수(CNT) 조합 `DAY_CNT` |
| 위치·시작·종료·항목·사용·적용 | PSTN·BGNG·END·ARTCL·USE·APLCN | N | – | 일반단어 |

- **일자 = YMD, 일시 = DT.** 업계 관행(`_DT` = 날짜)과 반대라 틀리면 약어 불일치가 대량으로 나온다.
- **상태·구분으로 끝나는 컬럼은 위반이다.** 공식 용어에 `상태`·`구분`으로 끝나는 것은 없다. 규칙 검사는 `*_STTS_CD`·`*_SE_CD`를 제안한다.
- 순번은 표준단어가 아니다(일련번호 SN의 이음동의어). 정렬은 순서(SEQ), 식별용 일련값은 일련번호(SN)를 쓴다.
- 감사 컬럼 단어: 등록 REG, 수정 MDFCN, 삭제 DEL, 생성 CRT, 변경 CHG, 갱신 UPDT, 아이디 ID, 식별자 IDNTFR.

## 분류어별 기본 도메인

공식 용어 13,142개(폐기 제외)가 참조하는 도메인을 집계한 결과다. 도메인명은 "분류명 + 타입 문자(N·C·V·D) + 길이[,소수]" 규칙을 따른다(범례는 파일에 없고 행에서 추론).

| 분류어 | 기본 도메인 | 타입 | 근거 (용어 수) |
|---|---|---|---|
| 코드 | 코드C1~C12 (C2 최다) | CHAR(n) | 78 |
| 명 | 명V100 (V200, V300) | VARCHAR(n) | 2,272 |
| 번호 | 번호V20 / V50 | VARCHAR(n) | 1,167 |
| 일련번호 | 일련번호N22 (N10) | NUMERIC(22) | 159 |
| 일자 | 연월일C8 | CHAR(8) YYYYMMDD | 1,827 (예외 없음) |
| 일시 | 연월일시분초D | DATETIME | 855 (예외 없음) |
| 여부 | 여부C1 | CHAR(1) Y/N | 1,422 (예외 없음) |
| 순서 | 순서N10 | NUMERIC(10) | 104 |
| 일수 | 수N7 | NUMERIC(7) | 85/93 |
| 수량 | 수N10,3 | NUMERIC(10,3) | 100/109 |
| 단가·금액 | 금액N15 (N18) | NUMERIC(15) | 단가 44, 금액 776/796 |
| 내용 | 내용V4000 | VARCHAR(4000) | 863/867 |

- 일자·일시·여부는 예외가 없으므로 기본값이 아니라 **강제 규칙**으로 다룬다.
- `연월일시분초C14`(문자형)는 있지만 쓰는 공식 용어가 0개다. 일시는 날짜형으로 본다.
- 표현형식은 화면 표시용이다. 도메인 파일과 용어 파일의 표기가 다른 경우가 있어 검증 기준에서 뺀다.

## 명명 규칙

고시가 정하는 것은 "용어 = 단어 + 도메인 조합"(제12조), "공식 용어의 약어 변경은 폐기 후 신규 제정"(제13조④)뿐이다. **대소문자·구분자·최대 길이·테이블 접두어·PK/FK 명명은 고시에 없다.** 세부 규칙이 있을 가능성이 큰 「공공데이터베이스 표준화 관리 매뉴얼」(2023.4)은 확보하지 못했다.

| 규칙 | 등급 | 근거 |
|---|---|---|
| 약어는 대문자 ASCII 2~6자 | observed | 공식 단어 3,284개 전수 (2자 68, 3자 472, 4자 1,469, 5자 964, 6자 311) |
| 단어 약어를 `_`로 연결 | observed | 적용시작일자 = `APLCN_BGNG_YMD` |
| 분류어가 마지막 단어 | observed | 공식 용어 전수 관찰, 업계 정의 |
| 공식 용어 약어 변경 금지 | official | 고시 제13조④ |
| DDL은 소문자 snake_case | project | PostgreSQL은 따옴표 없는 식별자를 소문자로 접는다 ([PostgreSQL 18](https://www.postgresql.org/docs/18/sql-syntax-lexical.html)) |
| 식별자 63바이트 초과 거부 | official (PostgreSQL) | 초과분은 오류 없이 잘려 `<table>_<col>_fkey` 같은 제약명이 충돌할 수 있다 |
| 용어당 최대 단어 수, 접두어, PK·FK 명명 | project | 국가 규칙 없음. 점검 도구 설정값(5단어)은 참고만 한다 |

## 표준 준수 진단

- 법정 의무: 기관장은 매년 1회 이상 표준화 수준을 점검한다(제17조), 시정요구 후 3개월 안에 조치한다(제18조②). 신규 DB는 공통표준을 반드시 적용하되 적용이 어려우면 선별 적용할 수 있다(제8조⑤, 제10조⑤). 이 예외 조항이 `rules.yaml`의 면제 사유 근거다.
- **공식 준수율 산식·분모·합격 기준은 공개 자료에서 찾지 못했다.** 그래서 준수율은 프로젝트 정의(`project`)다: 점검 항목별 적합 컬럼 수 ÷ 진단 대상 컬럼 수 × 100.
- 점검 항목(SC-01~06)은 사전 구조에서 바로 나온다. 국내 점검 도구 관행([prodskill](https://prodskill.com/ko/data-standard-checker-3-standard-dictionary/))을 참고했다.
  - SC-01 사전에 없는 단어: 컬럼명을 끝에서부터, 긴 단어를 먼저 매칭해 분해한다("주민등록번호"를 "번호"로 먼저 쪼개지 않는다).
  - SC-02 분류어 미사용: 마지막 단어가 형식단어인지. `STTS`·`SE`로 끝나는 컬럼이 걸린다.
  - SC-03 분류어-도메인 불일치, SC-04 금칙어(이음동의어는 경고), SC-05 공식 용어와 동명이형, SC-06 타입·길이 불일치.
- 검사기는 공식 용어의 약어를 자동으로 바꾸지 않는다(제13조④).

## PostgreSQL 타입 프로필

NUMERIC·VARCHAR·DATETIME은 그대로 옮겨지지만 CHAR 기반인 일자·여부는 표준과 PostgreSQL 관용이 갈린다. 두 프로필을 `domains.yaml`의 한 매핑에서 만든다.

| 도메인 | `strict` (표준 저장 형식, 기본) | `pg_native` |
|---|---|---|
| 코드Cn | `varchar(n)` + 길이 CHECK | `varchar(n)` + 공통코드 FK |
| 명·번호 | `varchar(n)` | `varchar(n)` |
| 일련번호N22 | `numeric(22)` | `bigint` identity (19자리 → 편차) |
| 연월일C8 | `char(8)` + 숫자 8자리 CHECK | `date` |
| 연월일시분초D | `timestamp(0)` | `timestamptz(0)` |
| 시분초C6 | `char(6)` + CHECK | `time(0)` |
| 여부C1 | `char(1)` + `IN ('Y','N')` CHECK | `boolean` |
| 순서N10 | `numeric(10)` | `integer` (10자리 미만) |
| 수N10,3 | `numeric(10,3)` | `numeric(10,3)` (float 금지) |
| 금액N15 | `numeric(15)` | `bigint` (`money` 금지) |
| 내용V4000 | `varchar(4000)` | `text` + 길이 CHECK |

- 기본은 `strict`다. 팩의 목적이 공통표준 준수를 보이는 것이기 때문이다 (제안, ADR-0009).
- `char(n)`은 PostgreSQL에서 공백 패딩 때문에 느리다고 문서가 안내한다 ([PostgreSQL 18 §8.3](https://www.postgresql.org/docs/18/datatype-character.html)). 그래서 코드는 `varchar(n)` + CHECK로 둔다.
- 진단 도구가 `date`·`boolean`을 연월일C8·여부C1에 적합하다고 인정하는지는 확인하지 못했다. `pg_native`는 편차 목록과 함께 쓰는 선택 프로필이다.

## 남은 공백

- 「공공데이터베이스 표준화 관리 매뉴얼」(2023.4)과 연도별 「품질관리 수준진단·평가 매뉴얼」을 확보하면 `observed`·`project` 항목 일부를 `official`로 바꾸거나 고칠 수 있다.
- 8차 단어 집합의 약어 중 PostgreSQL 예약어와 충돌하는 것은 아직 전수 검증하지 않았다(`reserved_words_source`).
